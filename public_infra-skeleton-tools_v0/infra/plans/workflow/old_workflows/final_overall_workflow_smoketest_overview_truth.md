# Final Overall Workflow + Dynamic Smoke-Test - Overview Truth

Canonical workflow map for skeleton batches, organ batches, dynamic idempotent smoke checks, companion updates, and final operator/config integration.

## 1. Canonical truth model

| Area | Canonical rule |
|---|---|
| Shared project root | `/workspace` is the shared project workspace for code, runs, artifacts, models, outputs, and generated platform files. |
| Skeleton evidence | `/mnt/egress/dev-recordings/skeleton/<batch-slug>/` with `POSTCHECK.md` and `INTEGRATION_REQUEST.md`. |
| Organ evidence | `/mnt/egress/organs/dev-recordings/organs/<batch-slug>/` with `POSTCHECK.md` and `INTEGRATION_REQUEST.md`. |
| Skeleton companion | `/mnt/ingress/infra/skeleton/companion/<batch-slug>/COMPANION.md`. |
| Organ companion | `/mnt/ingress/infra/organs/companion/<batch-slug>/COMPANION.md`. |
| Config edits | Never edit config/lv/workflow during skeleton or organ implementation batches. Only vmuser/operator config-integration batches may do that. |
| Missing files | Stop, list exact missing files, classify required/optional, and do not invent evidence. |
| Live actions | Smoke tests must be safe and idempotent. No terraform apply, no kubernetes destructive change, no live RunPod creation, no real organ action unless explicitly gated. |

## 2. Overall order of work

| Phase | Do this | When smoke runs | When companion updates | Who changes config |
|---:|---|---|---|---|
| 1 | Run all skeleton batches first: skeleton 01, skeleton 02, ... skeleton 24. | After every skeleton batch and again at skeleton-complete. | After logical groups, after contract changes, or after skeleton-complete. | Nobody. Config is not edited here. |
| 2 | Generate/update skeleton companions as you go or after logical groups. | Use the latest smoke report as input to companion update. | S-T6. Companion documents checked skeleton state. | Nobody. |
| 3 | Then run organ batches: organ R01, organ R02, ... organ R12. | After every organ batch and again at organ-complete. | After organ logical groups, after safety/output contract changes, or after organ-complete. | Nobody. |
| 4 | Do final operator/config integration from completed evidence. | Run pre-config before integration and post-config after integration. | Use final companions as evidence. | Only vmuser/operator config-integration batch edits config/lv/workflow. |

## 3. Dynamic idempotent smoke-test architecture

| Layer | Path | Purpose | Created/updated by |
|---|---|---|---|
| Protocol/spec | `/workspace/docs/IDEMPOTENT_SMOKETEST_DYNAMIC.md` | Defines safe dynamic smoke protocol, module contract, PASS/WARN/FAIL rules, and forbidden actions. | ChatGPT drafts; Codex may write to docs. |
| Orchestrator | `/workspace/scripts/smoke_current_state.sh` | Discovers and runs applicable smoke modules for current phase and platform state. | Codex writes/updates from the spec. |
| Smoke modules | `/workspace/tests/smoke.d/*.smoke.sh` | Specific safe checks for kubernetes, terraform, agentfield, runpod, grn, skeleton, organs, config. | Codex adds modules as platform capabilities expand. |
| Reports | `/workspace/runs/smoke/<timestamp-phase>/SMOKE_REPORT.md` | Current evidence: what ran, what passed/warned/failed, skipped optional checks, exact commands. | Generated by orchestrator. |

### Smoke command pattern

```bash
BATCH_SLUG="01-runtime-substrate" bash /workspace/scripts/smoke_current_state.sh skeleton-progress
BATCH_SLUG="R01-real-organ-foundation" bash /workspace/scripts/smoke_current_state.sh organ-progress
bash /workspace/scripts/smoke_current_state.sh skeleton-complete
bash /workspace/scripts/smoke_current_state.sh organ-complete
bash /workspace/scripts/smoke_current_state.sh pre-config
bash /workspace/scripts/smoke_current_state.sh post-config
```

## 6. Dynamic smoke modules: what they may consume and run

| Module example | Consumes | Safe commands allowed | Must not do |
|---|---|---|---|
| `00-core.smoke.sh` | `/workspace` layout; Python/package metadata; git status if available. | `test -d`; `python --version`; import checks; file existence checks. | No deletes; no installs unless explicitly allowed. |
| `10-skeleton.smoke.sh` | Skeleton `SPEC`/`RUN_INSTRUCTIONS`; skeleton outputs; `/mnt/egress/dev-recordings/skeleton/...` | Skeleton dry-run/dummy commands; schema/file checks; metadata checks. | No config edits; no live organs. |
| `20-organs.smoke.sh` | Organ `SPEC`/`RUN_INSTRUCTIONS`; skeleton companion contract; organ outputs. | Organ dry-run commands; contract-preserving output checks. | No guarded-real/live actions unless explicitly requested. |
| `30-grn.smoke.sh` | GRN module/config files, safe sample inputs, expected artifact contract. | Unit-level or dry-run GRN commands; no expensive training by default. | No long GPU jobs; no external live calls unless gated. |
| `40-kubernetes.smoke.sh` | Kubernetes manifests, kube config if present, namespace context. | `kubectl version --client`; `kubectl config current-context`; `kubectl diff --server-side` only if safe and configured. | No `kubectl apply/delete/scale/rollout restart`. |
| `50-terraform.smoke.sh` | Terraform directories/modules/providers, tfvars examples if safe. | `terraform fmt -check`; `terraform init -backend=false`; `terraform validate`. | No `terraform apply/destroy`; no remote state mutation. |
| `60-agentfield.smoke.sh` | AgentField configs, local manifests, dry-run commands. | AgentField validate/status/dry-run checks. | No production agent launch. |
| `70-runpod.smoke.sh` | RunPod config templates, credentials presence check only, dry-run wrappers. | Validate config shape; check env var presence without printing secrets. | No pod creation, billing actions, live jobs. |
| `90-config.smoke.sh` | Config/lv/workflow files, integration manifest, generated operator batch. | pre-config read-only checks; post-config status/health checks. | No config edits outside operator integration step. |

| Post-config verification | Codex vmuser/operator + user | Updated config/lv/workflow files and generated integration evidence. | Final `SMOKE_REPORT.md` and config integration `POSTCHECK.md`. | `bash /workspace/scripts/smoke_current_state.sh post-config` |

## 8. The one-page operating rule

ChatGPT creates batch plans, companion text, and integration manifests from named evidence files. Codex executes named batch files and exact smoke commands. Skeleton and organ Codex batches write code and evidence only. Dynamic smoke modules expand with the platform and stay safe/idempotent. Only the final vmuser/operator config-integration batch edits config/lv/workflow, and it is bracketed by pre-config and post-config smoke.
