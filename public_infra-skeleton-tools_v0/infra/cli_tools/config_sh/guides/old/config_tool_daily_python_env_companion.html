1. The core idea

Functions are global. Python packages are environment-specific. Your managed config functions can be available to every target, but when a function installs Python packages it must choose one explicit Python environment.
Account profileAIEngineer
Target roleai-engineer
Python env policyaiengineer
Target envPYTHON_ENV=aiengineer
Installerpip install into aiengineer

A virtualenv called experiment1 does not automatically see packages installed into base or aiengineer. That isolation is useful, but only if your installer functions do not silently install into the wrong place.

Do not rely on “whatever env is active”. A managed install step should resolve PYTHON_ENV from profile policy and print where it is installing.

3. Daily workflow

When creating a role user

  1. Create/reconcile the account from its account profile.
  2. Check config-show for the resolved PYTHON_ENV.
  3. Create the env manually if needed.
  4. Run only one role install step.
  5. Verify packages inside that env.

When starting an experiment

  1. Create a new env, for example experiment1.
  2. Override PYTHON_ENV for that target or profile.
  3. Run the one install step into experiment1.
  4. Keep experiment packages isolated from the role default env.
# inspect target policy
config --target aiengineer config-show

# inspect bootstrap plan/status
config --target aiengineer bootstrap steps
sudo config --target aiengineer bootstrap status

# run one env-targeted step only
sudo config --target aiengineer bootstrap step install_ml_base_python_stack

4. Source-of-truth file

The policy should live in one file, not scattered across installer functions.

/home/vmuser/.local/etc/config-sh/install/python-env-profiles.tsv

Suggested columns:

profile_name	target_role	python_env	env_manager	create_missing	allow_system	description

Suggested rows:

DefaultOperator	operator	operator	auto	0	0	Operator Python tools
DefaultTarget	target	target	auto	0	0	Generic target Python tools
AIEngineer	ai-engineer	aiengineer	auto	0	0	AI Engineer Python environment
ResearchScientist	research-scientist	researchscientist	auto	0	0	Research Scientist Python environment
Publisher	publisher	publisher	auto	0	0	Publisher Python environment
create_missing=0 means managed install steps do not create virtualenvs automatically. This is safer. You create the env first, then run the step into it.
allow_system=0 means do not install into system Python. This avoids breaking the OS Python or shared system packages.

5. Override to an experiment env

Sometimes you want a temporary or project-specific env such as experiment1. That should be explicit.

Option A — override the target policy

# in /home/vmuser/.local/etc/config-sh/targets/aiengineer.env
PYTHON_ENV="experiment1"

Option B — override the profile source of truth

# in python-env-profiles.tsv
AIEngineer	ai-engineer	experiment1	auto	0	0	AI Engineer experiment env
Use target override when only one user or one experiment should change.
Use source-of-truth override when every future user with that profile should use the new env.

Use base intentionally

PYTHON_ENV="base"

This is allowed as an explicit operator choice. It should not be the only possible behavior.

6. Run one env-targeted step

The installer should print the target env before doing package work.

sudo config --target aiengineer bootstrap step install_ml_base_python_stack

Expected output shape:

target user: aiengineer
target role: ai-engineer
target Python env: aiengineer
env manager: auto
installing packages from PIP_ML_BASE_STACK into aiengineer

For an experiment override:

target Python env: experiment1
installing packages from PIP_ML_BASE_STACK into experiment1
If output says it is installing into system, stop unless you explicitly set PYTHON_ENV_ALLOW_SYSTEM=1.

7. Check what is installed where

Conda-style checks

# list envs
sudo -H -u aiengineer bash -lc 'conda env list'

# check Python executable
sudo -H -u aiengineer bash -lc 'conda run -n aiengineer python -c "import sys; print(sys.executable)"'

# check package inside role env
sudo -H -u aiengineer bash -lc 'conda run -n aiengineer python -c "import numpy; print(numpy.__version__)"'

# check package inside experiment env
sudo -H -u aiengineer bash -lc 'conda run -n experiment1 python -c "import numpy; print(numpy.__version__)"'

venv-style checks

# example venv path convention
sudo -H -u aiengineer bash -lc '/home/aiengineer/.virtualenvs/aiengineer/bin/python -c "import sys; print(sys.executable)"'

sudo -H -u aiengineer bash -lc '/home/aiengineer/.virtualenvs/aiengineer/bin/python -m pip list'
The exact check depends on your environment manager. The policy file can say env_manager=auto, but the installer should still print what it resolved.

8. Common patterns

Stable role env

Use this for the normal daily toolset of a role.

AIEngineer -> aiengineer
ResearchScientist -> researchscientist
Publisher -> publisher

Temporary experiment env

Use this for trying package versions without contaminating the role env.

PYTHON_ENV="experiment1"

Base env

Use only when you intentionally want a shared base for that role/user.

PYTHON_ENV="base"

9. Troubleshooting

SymptomLikely causeFix
Package installed but import fails in experiment1 It was installed into a different env, probably base or role env Run the install step with PYTHON_ENV=experiment1
Installer uses system Python Env resolver fell back too far Set PYTHON_ENV explicitly and keep PYTHON_ENV_ALLOW_SYSTEM=0
Env not found create_missing=0 and env was not created yet Create the env manually, or intentionally set create_missing=1
Wrong env after profile edit Target env was not reconciled/refreshed Reconcile target policy and re-check config-show
Packages pollute base Role env default was set to base Use profile-aligned env: aiengineer, researchscientist, or publisher

10. Codex prompt for future env work

Read config.sh, installers.sh, and /home/vmuser/.local/etc/config-sh/install/python-env-profiles.tsv.

Make one Python-installing function environment-aware.

Requirements:
- Resolve PYTHON_ENV from target env policy.
- Do not use the currently active shell env silently.
- Do not install into system Python unless PYTHON_ENV_ALLOW_SYSTEM=1.
- Do not use sudo pip.
- Print the target env before installing.
- If the env is missing and PYTHON_ENV_CREATE_MISSING=0, skip or fail clearly.
- Run:
  bash --noprofile --norc -n /home/vmuser/.local/bin/config.sh
  bash --noprofile --norc -n /home/vmuser/.local/lib/config-sh/installers.sh
