## Current state expected before this correction

The current CIFS mount helper still builds mount options with inline username-only authentication, shaped approximately like this:

```bash
mount_cifs_opts() {
  local src="$1" dst="$2" extra="$3" fmode="$4" dmode="$5" smb_user="${6:-$SMB_USER}"
  sudo mount -t cifs "$src" "$dst" -o username="$smb_user",uid=$uid,gid=$shared_gid,$extra,file_mode=$fmode,dir_mode=$dmode,vers=3.0,sec=ntlmssp

```

That is better than passing a password, but it has two remaining problems:

1. If a password is needed, `mount.cifs` may prompt, which is bad for non-interactive use.
2. There is no supported way to provide credentials safely through a protected credentials file.

## Goal

Add a small credential-file layer for CIFS mounts.

Supported usage should include:

```bash
MOUNTS_CREDENTIALS_FILE="$HOME/.local/share/wsl-mounts/cifs.credentials" \
  bash "$HOME/.local/bin/config.sh" mount --all
```

and:

```bash
bash "$HOME/.local/bin/mounts.sh" run \
  --credentials-file "$HOME/.local/share/wsl-mounts/cifs.credentials" \
  --all
```

The credentials file should use the standard `mount.cifs` credentials-file format:

```text
username=your_smb_username
password=your_smb_password
# optional:
# domain=YOUR_DOMAIN
```

The script must never ask the user to type the password. It must only accept a path to a credentials file.

## Required behavior

### Default behavior

If no credentials file is configured, preserve current behavior as much as possible:

```bash
sudo mount -t cifs ... -o username=<existing user>,uid=...,gid=...,file_mode=...,dir_mode=...,vers=3.0,sec=ntlmssp
```

This keeps the patch low-risk and avoids forcing a credential-file migration immediately.

### Credentials-file behavior

If a credentials file is configured, use:

```text
credentials=/path/to/file
```

instead of:

```text
username=<user>
```

The resulting mount options should look conceptually like:

```text
credentials=/home/vmuser/.local/share/wsl-mounts/cifs.credentials,uid=1000,gid=1001,file_mode=0660,dir_mode=0770,vers=3.0,sec=ntlmssp
```

Do not combine `credentials=...` and `username=...` unless you have a specific reason. The credentials file should be the auth source when present.

### Credential-file validation

Before using a credentials file, validate it.

Required checks:

- Path is non-empty.
- Path points to a regular file.
- File is readable.
- File permissions are not group-readable, group-writable, group-executable, world-readable, world-writable, or world-executable.
- Path does not contain a comma, because commas split CIFS mount options.
- File contains a `username=` line.
- File contains a `password=` line.

Recommended permission rule:

```text
0600 or stricter
```

A file with `0644`, `0660`, `0777`, or similar must be rejected with a clear error message.

Keep the validation simple. This is a Bash script, not a secrets manager.

## Suggested implementation shape

Add helper functions near the other `mounts_` helpers in `mounts.sh`.

Example:

```bash
mounts_credentials_file_default() {
  printf '%s' "${CURRENT_HOME}/.local/share/wsl-mounts/cifs.credentials"
}

mounts_validate_credentials_file() {
  local file="$1"

  [[ -n "$file" ]] || { echo "[ERROR] Empty credentials file path" >&2; return 1; }
  [[ "$file" != *,* ]] || { echo "[ERROR] Credentials file path must not contain commas: $file" >&2; return 1; }
  [[ -f "$file" ]] || { echo "[ERROR] Credentials file not found: $file" >&2; return 1; }
  [[ -r "$file" ]] || { echo "[ERROR] Credentials file is not readable: $file" >&2; return 1; }

  if find "$file" -perm /077 -print -quit | grep -q .; then
    echo "[ERROR] Credentials file is too permissive; run: chmod 600 '$file'" >&2
    return 1
  fi

  grep -qE '^[[:space:]]*username=' "$file" || { echo "[ERROR] Credentials file missing username= line: $file" >&2; return 1; }
  grep -qE '^[[:space:]]*password=' "$file" || { echo "[ERROR] Credentials file missing password= line: $file" >&2; return 1; }
}

mounts_cifs_auth_option() {
  local fallback_user="$1"
  local credentials_file="${2:-}"

  if [[ -n "$credentials_file" ]]; then
    mounts_validate_credentials_file "$credentials_file" || return 1
    printf 'credentials=%s' "$credentials_file"
  else
    printf 'username=%s' "$fallback_user"
  fi
}
```

If you use a default credentials-file path, only auto-use it if the file exists. Do not fail simply because the default file is absent.

Recommended pattern:

```bash
MOUNTS_CREDENTIALS_FILE="${MOUNTS_CREDENTIALS_FILE:-}"

if [[ -z "$MOUNTS_CREDENTIALS_FILE" ]]; then
  default_credentials_file="$(mounts_credentials_file_default)"
  if [[ -f "$default_credentials_file" ]]; then
    MOUNTS_CREDENTIALS_FILE="$default_credentials_file"
  fi
fi
```

This lets the system become safer automatically once the user creates the standard file, while keeping legacy behavior if no file exists.

## Update `mount_cifs_opts`

Refactor the nested `mount_cifs_opts` helper inside `mounts_mount_smb_folders` so it uses the auth helper.

Recommended shape:

```bash
mount_cifs_opts() {
  local src="$1" dst="$2" extra="$3" fmode="$4" dmode="$5" smb_user="${6:-$SMB_USER}" credentials_file="${7:-${MOUNTS_CREDENTIALS_FILE:-}}"
  local auth_opt opts

  auth_opt="$(mounts_cifs_auth_option "$smb_user" "$credentials_file")" || return 1

  opts="$auth_opt,uid=$uid,gid=$shared_gid"
  [[ -n "$extra" ]] && opts="$opts,$extra"
  opts="$opts,file_mode=$fmode,dir_mode=$dmode,vers=3.0,sec=ntlmssp"

  sudo mount -t cifs "$src" "$dst" -o "$opts"
}
```

This also avoids a double comma when `extra` is empty.

If implementing share-specific credentials, pass the share-specific file as the 7th argument:

```bash
mount_cifs_opts "$src_distrohome" "$distrohome_mount" "" "0660" "0770" "$SMB_USER_MAIN" "${MOUNTS_CREDENTIALS_DISTROHOME:-${MOUNTS_CREDENTIALS_FILE:-}}"
```

Apply the same pattern to scripting, ingress, and egress only if share-specific overrides are implemented.
